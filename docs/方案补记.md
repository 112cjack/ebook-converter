# 技术方案补记（V1.0 实现期裁决记录）

依据《电子书转换器技术方案》末段约定："若实现过程中出现方案未覆盖的决策点，按『保持轻量、复用优先』原则就近裁决并在对应文档中补记。"以下为 M2 至 M4 实现期间的全部裁决，均已随代码落地并有测试覆盖。

## 1. 新增 POST /api/remove 接口（第八组）

- **背景**：方案表 5 规定七组接口，但已评审的界面原型包含「移除单个文件 / 清空列表」交互，需要服务端配合。
- **裁决**：新增 `POST /api/remove`（body 可选 `upload_ids`，缺省清空全部可移除项）。移除仅作用于列表展示与临时上传文件；任务记录保留，作为本次运行的转换历史（对应功能 F6）。
- **连带规则**：转换中（converting）的文件不可移除；排队中（queued）的文件允许移除，其任务置为 skipped（消息"已从列表移除"），worker 不会执行。

## 2. Web 版输出目录的默认值

- **背景**：方案 4.4 的"默认为上传时选择的目录下 converted 子目录"沿用命令行版约定，但网页上传没有"选择的目录"概念。
- **裁决**：输出目录按三级解析——转换请求显式指定 > 设置中的默认输出目录（F7）> 程序目录下 `converted`。不再自动嵌套 `converted` 子层；`open-folder` 只放行服务层登记过的目录（转换提交、设置保存时登记）。

## 3. 应用工厂与启动入口的文件归属

- **背景**：方案 4.1 称 `app.py` 负责应用工厂、端口绑定与启动，第 6 章目录树则把应用工厂标注在 `webapp/__init__.py`，两处不一致。
- **裁决**：两者兼顾——`webapp/__init__.py` 提供 `create_app()` 应用工厂（目录树标注），`webapp/app.py` 作为启动入口负责端口探测（7788 起自动递增）、控制台提示与自动打开浏览器（4.1 描述），以 `python -m webapp.app` 或 `start.bat` 启动。

## 4. 进度百分比在 stdout 而非 stderr

- **背景**：方案第 9 章对策写"解析引擎 stderr 的进度百分比"。
- **实测**（Calibre 9.15.0）：ebook-convert 把进度与日志输出到 **stdout**（形如 `67% 正在运行 EPUB Output 插件`，以 `\r\n` 结尾），stderr 在成功时为空、失败时才是错误信息。
- **裁决**：`ebook_converter.convert_file` 新增可选 `on_progress` 回调（流式读 stdout 解析 `N%`，只增不减；stderr 照常收集用于错误信息）。不传回调时沿用原 `communicate` 路径，既有行为零变化。方案中的"stderr"按实测更正为"stdout"。

## 5. 界面图标不使用 CDN

- **背景**：原型引用 unpkg 的 lucide 图标库。
- **裁决**：产品要求断网可用、文件不出本机，正式界面把所需 9 个图标改为内联 SVG symbol，零外部请求。

## 6. 打包产物命名

- **裁决**：PyInstaller 产物命名为 `ebook-converter.exe`（与仓库名一致，避免个别环境对中文可执行文件名的兼容性问题）；构建脚本 `build_exe.bat`，`.gitignore` 排除 `build/ dist/ *.spec`。
- **V1.1 更正**：中文产物名实测通过，产物已改为 `dist\电子书转换器.exe`，并新增桌面快捷方式接口（见第 8 条）。

## 7. V1.1 新增接口（第九至十二组）

- `POST /api/cancel`：取消转换中的任务（body `task_id`）。任务状态机新增 `cancelled`（已取消）；引擎层 `convert_file` 新增可选 `cancel_check` 回调，仅流式路径生效（每至多 1 秒轮询一次），取消时杀子进程并清理残缺输出，CLI 路径与既有行为零变化。
- `GET /api/browse?path=`：输出目录浏览器数据源；`path` 为空返回盘符列表（尾部带分隔符，可直接下钻），否则枚举该目录下的子目录（过滤 `.`/`$` 开头隐藏项）。
- `POST /api/install-engine`（body `mode: portable|winget`）：后台线程安装引擎，进度经 `/api/status` 的 `engine.install` 字段轮询；同一时刻仅允许一个安装任务（409）。
- `POST /api/create-shortcut`：经 PowerShell `WScript.Shell` 在用户真实桌面（`[Environment]::GetFolderPath('Desktop')`）创建「电子书转换器.lnk」；仅打包版（`sys.frozen`）可用，`/api/status` 新增 `frozen` 字段供界面显隐入口。

## 8. 便携版引擎与探测优先级

- 探测顺序调整为：**程序目录 `engines\calibre`（含一级子目录，兼容官方便携版解压结构）> 设置手动路径 > PATH 与常见安装位置**。
- 便携版获取：`POST /api/install-engine {mode:"portable"}` 下载官方便携版安装器（`https://calibre-ebook.com/dist/portable`）并以目标目录参数无人值守解压到程序目录。
- **实测结论**（2026-10-31）：`dist/portable` 入口有效（302 重定向至官方下载服务器），但该下载服务器在本机网络直连超时（WinError 10060）。下载失败属预期风险，安装器失败状态会明确提示改用 winget 或官网手动下载，引导页两个动作始终可用。

## 9. 覆盖重转与同格式跳过

- `POST /api/convert` 新增可选 `overwrite`（布尔）：为 True 时 worker 在转换前删除已存在的同名输出；**同批重名保护优先于覆盖删除**（同批两个文件输出重名时仍跳过后者）。
- 源格式与目标格式相同的上传直接建 `skipped` 任务（消息「源文件已是 X 格式，无需转换」），不入队。

## 10. 长文件名截断与启动清理

- `safe_filename` 对主名截断至 80 字符（保留扩展名），返回截断标记 `truncated`，界面对应行提示——规避 Windows MAX_PATH（260 字符）限制下 tmp 路径 + 输出路径超长导致的转换失败。
- `create_app` 启动时清空并重建上传目录（此前仅依赖 atexit，进程强杀会残留）；atexit 保留作双保险。

以下为 **V1.2**（2026-11-01，依据 `docs/改进方案-V1.2.md`）新增裁决：

## 11. 引擎显示状态矛盾修复（bug）

- **现象**：右上角胶囊显示"已就绪"而底部提示行显示"未检测到"，三处 UI 各自刷新不同步。
- **修复**：`GET /api/tasks` 响应附带 `engine` 字段，前端每轮轮询同步并重渲全部引擎相关 UI；提示行区分「正在检测引擎…」（状态未取得）与「未检测到转换引擎」（明确未安装）；状态获取失败时置回检测中。

## 12. 文件夹监听（F8）

- 新增 `GET /api/watch`（查询时**同步执行一轮巡检**——单层目录扫描毫秒级，保证页面轮询即得实时结果；后台线程按 5~60 秒间隔兜底维持 fresh 提示语义）与 `POST /api/watch`（启用/停用/修改规则，随 `settings.json` 持久化，重启自动恢复）。
- 违规两档：`unconvertible`（程序无法识别/转换）与 `wrong_format`（可转换但非期望格式）；跳过最近 10 秒内修改的文件（防复制中半成品误报）；文件夹不可达显示"暂时不可达"不报错；新违规一次性提示（文件移走后再出现会重新提示）。
- 设置字段：`watch_enabled / watch_folder / watch_format / watch_interval`，布尔字段读取时强转。

## 13. 品牌 logo

- 顶栏印章采用并行原型会话定稿的简约「渡」印 SVG（方章 + 七笔简化笔画，随主题变色）；产品名暂保持「电子书转换器」，候选名「书渡」待正式拍板。
