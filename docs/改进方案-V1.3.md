# 改进方案 V1.3：多规则监听、转换预设、历史导出、引导卡与工程固化

项目：书渡（电子书转换器）｜ 日期：2026-11-01 ｜ 编制：112cjack
依据：用户确认的改进建议清单（全部采纳）。

## 1 转换预设（阅读设备优化）

- 引擎层新增 `CONVERSION_PRESETS`：`default`（无参数）、`kindle`（`--output-profile kindle`）、`eink`（`--output-profile generic_eink`）。预设值随 Calibre 官方 profile 列表，不暴露裸参数。
- `build_command(engine, src, dst, options=None)` 与 `convert_file(..., options=None)` 新增可选参数：把预设参数附加到命令尾部；不传时行为零变化（CLI 不受影响）。
- 服务层 `/api/convert`、`/api/watch-convert` 新增可选 `preset`（缺省 default，非法值 400）；任务记录携带 preset。
- 界面：操作栏「阅读设备」下拉（自动 / Kindle / 电子墨水屏），默认自动。

## 2 多条监听规则（含自动转换）

- 设置结构改为 `watch_rules: [{id, folder, format, auto_convert}]`；读取时从旧单规则字段（watch_enabled/watch_folder/watch_format）一次性迁移，旧字段不再使用。规则文件夹唯一（重复提交 400）。
- `watcher.py` 重构为多规则巡检：违规记录携带 `rule_format`（期望格式），fresh 语义按路径维持；文件夹不可达按条目报告。
- **自动转换**：规则级开关 `auto_convert`（默认关）。巡检发现新违规（fresh）且为「格式不符」档时自动按该规则期望格式创建转换任务（走复制链路，源文件不动）；同一文件内容未变化（mtime+size 相同）不重复转换；引擎缺失时跳过本轮自动转换（不影响提示）。
- API：`GET /api/watch` → `{rules, violations, fresh}`；`POST /api/watch` body 为 `{rules: [...]}` 整体提交（服务端生成 id）；`/api/watch-convert` 按违规记录的 `rule_format` 分组转换。
- 界面：设置对话框监听区改为规则列表（每条：文件夹 + 期望格式 + 自动转换开关 + 删除），可添加多条；监听卡违规行展示期望格式，一键转换按行格式分组。

## 3 历史导出 CSV

- `GET /api/history.csv`：本次运行全部任务导出（时间、文件名、源格式、目标格式、状态、结果信息、输出路径），UTF-8 with BOM（Excel 直接打开不乱码）。
- 界面：历史对话框新增「导出 CSV」按钮（浏览器直接下载）。

## 4 首次使用引导卡

- 纯前端：localStorage 记忆（`seen_intro`），首次打开显示三步引导卡（导入 → 选格式与设备 → 开始转换，并提示监听/主题入口），「开始使用」关闭后不再出现。

## 5 工程固化

- **冒烟脚本入库**：`scripts/smoke.py`——起服务（或连指定 exe），检查关键接口与页面元素，输出 PASS/FAIL 清单，非零退出码表示失败；README 开发节说明用法。
- **双会话协作规则**：写入项目 `AGENTS.md`——原型会话只改 `prototype/` 与 `docs/` 设计稿；正式版 `webapp/static` 视觉改动由原型会话完成并**自行 commit**后知会用户，由功能会话验证合入；功能会话改 `webapp/` 后端与功能前端；任何一方 `git add` 前必须 `git status` 分辨归属；打包前必须确认旧进程已退出。
