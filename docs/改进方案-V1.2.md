依据：用户反馈（页面状态矛盾 bug、文件夹监听需求）与已确认的实施建议；logo 采用并行原型会话定稿的简约「渡」印（prototype/界面原型.html，commit 74a2aab）。

## 1 检测状态同步修复（bug）

- **根因**：引擎状态仅页面加载时获取一次，右上角胶囊/顶部引导条只在 loadStatus 刷新，底部提示行由任务轮询驱动——状态过期或获取失败后三者各说各话。
- **修复**：`GET /api/tasks` 响应附带 `engine` 字段，前端每轮轮询同步 `state.engine` 并重渲三处 UI（单一数据源持续同步）；底部文案区分「正在检测引擎…」（engine 为 null）与「未检测到转换引擎」（明确未安装）；loadStatus 失败时把界面置回「检测中」，不留过期画面。

## 2 文件夹监听（新功能 F8）

需求：用户指定一个文件夹并设置规则（该文件夹内文件必须全部为某格式），程序持续巡检，出现不符文件时提示；规则持久化，程序重启自动恢复（"记忆"）。

- **机制**：后台守护线程定时轮询（默认 5 秒，5~60 可设置），扫描文件夹第一层，复用引擎层白名单；不引入文件系统事件库（轻量原则）。
- **规则**：先支持单条规则（监听文件夹 + 期望格式），数据按可扩展结构设计；存 `settings.json` 新字段 `watch_enabled / watch_folder / watch_format / watch_interval`。
- **违规两档**：`unconvertible`（程序无法识别/转换的文件）与 `wrong_format`（能转换但非期望格式）。
- **提示**：页面顶部监听状态卡（常显：监听中 · 路径 · 期望格式 · 违规数，点击展开文件列表）；新违规首次出现时 toast 一次（后端维护已提示集合，文件移走后再出现会再次提示）；不做弹窗轰炸。桌面通知列第二批。
- **防误报**：跳过最近 10 秒内修改的文件（写入中的半成品）；文件夹不可达（U 盘拔出等）显示「文件夹暂时不可达」，不报错。
- **接口**：`GET /api/watch`（规则 + 状态 + 违规列表 + 本轮新增标记）、`POST /api/watch`（启用/停用/修改规则并持久化；期望格式须在 OUTPUT_FORMATS 内，启用时文件夹必填）。`GET /api/tasks` 同时新增 `engine` 字段（第 1 节）。
- **界面**：设置对话框新增「文件夹监听」区（开关 + 目录选择（复用目录浏览器）+ 期望格式下拉）；主区顶部监听状态卡仅启用时显示。

## 4 测试与验收

- 服务层：违规分类（两档/期望格式忽略/隐藏文件忽略/10 秒内新文件跳过）、不可达文件夹、fresh 一次性提示语义（移除再出现可再提示）、/api/watch 校验与持久化、/api/tasks 携带 engine。
- 手工验收：启用监听 → 放入不符文件 → 状态卡出现且 toast 一次 → 移走文件违规消除 → 重启程序监听自动恢复；三个引擎显示位置始终一致。
