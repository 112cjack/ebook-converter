# 改进方案 V1.4：稳定底座（按路径自动转换、统一引擎探测、离线安装、前端拆分）

项目：书渡（电子书转换器）｜ 日期：2026-11-05 ｜ 编制：协作会话
依据：代码库审阅结论 + 用户确认的推荐路线与方案 A（最小手术）。

## 0 背景与定调

- 现状：Python / Flask / waitress + Calibre `ebook-convert`；CLI + Web；多规则监听 / 自动转换 / 预设 / CSV / 主题 / 引导 / exe；V1.1–V1.3 已落地；约 130 tests 通过。
- 审阅结论：不必大重构。路线为 **V1.4 稳 → V1.5 强 → V1.6 亮**。
- 本次范围：**只做完 V1.4**。落地选 **方案 A 最小手术**（改现有模块，不换架构）。
- UI：功能必需改动 + 顺手视觉打磨 + 拆分 `app.js`；**不大改版**。
- 自动转换落盘策略（已确认）：**直接按源路径转换**，不把监听文件整份读入再复制进上传目录。

P0 问题（V1.4 必须消化）：

1. `make_auto_convert_handler` 对源文件 `read_bytes()` 再 `store_upload`，大文件易爆内存/拖慢。
2. CLI 的 `ebook_converter.find_engine` 与 Web 的 `make_engine_resolver`（含 `engines/calibre`）不一致。
3. 便携 Calibre 在线下载常超时，缺可靠离线安装路径。

## 1 目标 / 范围 / 成功标准

### 目标

把书渡做成「大文件与离线场景下仍稳」的底座：自动转换按路径、引擎探测统一、安装可离线，前端可维护，不为 V1.5+ 功能提前铺大框架。

### 范围内

- 自动转换：任务携带源绝对路径，worker 直接 `convert_file(src→dst)`；源文件不移动、不整文件复制进 `tmp/uploads`。
- 上传转换：`POST /api/convert` 改为流式写入临时文件（语义与响应字段尽量不变）。
- 引擎：`ebook_converter` 提供统一 `resolve_engine`（或等价）；CLI 与 Web 同序；Web 保留版本缓存等专属逻辑。
- 安装：保留 `portable` / `winget`；新增本地安装包（上传到 `tmp` 后复用现有静默解压）。
- 前端：无构建拆分 `webapp/static/app.js`；CSS 小打磨（间距、空状态、按钮层次、安装文案区）。
- 测试与文档：补测 + README / 方案补记更新。

### 范围外（归 V1.5+）

- k2pdfopt / 扫描 PDF、递归监听、多输出格式、USB / Kindle 设备监听。
- 引入前端打包工具、重做信息架构、换 WSGI / 任务持久化方案。

### 成功标准

- 自动转换大文件不再因整文件 `read_bytes` 复制而失败或明显占内存；任务源为监听目录内路径。
- CLI 与 Web 引擎查找顺序一致，且能解析到 `base/engines/calibre`（含官方解压一级子目录）。
- 无网时可选用本地官方便携安装包完成安装（失败有明确提示，不静默改走外网下载）。
- `app.js` 已拆分；UI 仅顺手打磨。
- 现有测试全绿 + 新增相关测试通过。

## 2 架构与数据流

保持现有四层，不新增框架：

```text
CLI / Web UI
    ↓
webapp（Flask API + TaskManager + FolderWatcher + installer）
    ↓
ebook_converter.py（统一 resolve_engine + convert_file）
    ↓
Calibre ebook-convert
```

### 2.1 引擎探测下沉

- 在 `ebook_converter.py` 提供统一入口，例如 `resolve_engine(base_dir=None, manual_path=None)`。
- 顺序：`base_dir/engines/calibre`（含一级子目录）→ 手动路径 → 现有 PATH / 常见路径（即今天 `find_engine` 逻辑）。
- `webapp.make_engine_resolver` 改为薄包装；CLI `main` 也走同一函数。
- Web 专属的版本缓存、安装状态仍留在 `webapp`。

### 2.2 任务源文件：上传 vs 监听路径

- 上传任务：仍落在 `tmp/uploads/`（改为流式写入）。
- 自动转换任务：记录带 **源绝对路径**（来自已登记的 `watch_rules.folder`），**不复制**。
- worker：有 `source_path` 则 `convert_file(源路径 → 输出目录/名)`；否则走既有上传文件路径。
- 安全：创建任务时校验 `Path(src).resolve()` 落在某条规则 folder 之下；不把任意路径开放给 API 乱转。

### 2.3 安装引导

- 保留 `portable | winget`。
- 新增本地包模式：引导对话框「选择已下载的安装包」→ 上传到 `tmp/` → 复用现有静默解压；另保留官网下载页链接作退路。
- 优先上传到服务临时目录，少用浏览器直接读任意盘符。

### 2.4 前端拆分（无构建）

- `index.html` 多 `<script>` 加载，例如：`api.js` / `state.js` / `render.js` / `watch.js` / `settings.js` / `app.js`（入口）。
- 优先 **多 script + 同一命名空间**（兼容当前非 module 写法）；不引入打包工具。
- 视觉：只动 CSS 变量间距、空状态、按钮层次、安装引导文案区。

### 2.5 自动转换数据流

```text
Watcher 发现 wrong_format 且 auto_convert
  → 校验路径 ∈ 规则 folder
  → TaskManager 建任务（source_path=原文件, format=规则格式）
  → worker：resolve_engine → convert_file(源路径 → 输出目录)
  → 源文件不动；成功/失败回写；指纹去重逻辑保持
```

## 3 接口 / 错误处理 / 测试

### 3.1 API / 行为变更（尽量兼容）

| 点 | 行为 |
|----|------|
| `POST /api/convert`（上传） | 流式落盘到 `tmp/uploads/`；语义与响应字段不变 |
| 自动转换任务 | **无新公开 API**；内部任务增加 `source_path`（或等价）；worker 按路径转 |
| 引擎探测 | CLI / Web 共用统一 resolve；状态相关对外字段尽量不变 |
| 安装引导 | 保留 portable/winget；新增本地上传安装（如新接口或 `mode=local`） |
| 打开文件等 | 仍只允许任务相关路径；不扩大任意路径读取 |

### 3.2 错误处理

- **路径越界**：任务失败，文案明确「源文件不在监听目录内」，不调用转换。
- **源文件消失 / 占用**：转换失败记入任务错误；不重试刷屏（保持现有去重 / 失败策略）。
- **流式上传中断**：删除半成品临时文件，返回错误，不建成功任务。
- **本地安装包**：校验扩展名与大致大小；解压失败回滚临时目录并提示「安装包无效或损坏」；**不**静默回退去外网下载。
- **引擎未找到**：CLI 与 Web 错误信息对齐，并引导安装页。

### 3.3 测试（在现有基础上补）

1. `resolve_engine`：`engines/`、子目录、手动路径、PATH；CLI 与 Web 同序。
2. 自动转换按路径：watcher → 任务带 `source_path` → mock `convert_file` 断言入参为源绝对路径且未整文件复制进 uploads。
3. 路径安全：规则外路径建任务被拒。
4. 流式上传：写入成功；中断清理（可用小 chunk 模拟）。
5. 本地安装包：坏包失败不留脏目录；好包走解压钩子（可 mock）。
6. 回归：自动转换、指纹、上传转换、engine API 仍绿。

### 3.4 刻意不做

- V1.5+ 功能；前端大改版与打包工具；破坏性任务持久化格式变更（新字段默认兼容，旧记录缺 `source_path` 时仅新任务走路径分支）。

## 4 文件级改动与风险

### 4.1 预计改动面

| 区域 | 文件 | 改什么 |
|------|------|--------|
| 引擎层 | `ebook_converter.py` | 统一 `resolve_engine`；保持 `convert_file` 吃路径；`find_engine` 可保留为无 base 的薄封装或委托 |
| Web 装配 | `webapp/__init__.py` | `make_engine_resolver` 改调统一函数；`make_auto_convert_handler` **去掉** `read_bytes` + `store_upload`，改为按路径建任务 |
| 任务 / Worker | `webapp/tasks.py` | 任务支持 `source_path`；worker 分支：有源路径则直接转 |
| API | `webapp/api.py` | 上传流式写入；安装增加 local/upload；路径安全校验（若建任务入口在此） |
| 安装 | `webapp/installer.py` | 支持本地包解压入口，复用便携解压逻辑 |
| 监听 | `webapp/watcher.py` | 行为基本不变；回调语义从「复制后转」变为「按路径建任务」（若签名需调则同步） |
| 前端 | `webapp/static/app.js` → 拆分多个 js；`index.html`；`style.css` | 安装入口 + 小打磨；`build_exe` / spec 资源清单带上新 js |
| 测试 | `tests/test_ebook_converter.py`、`tests/test_webapp.py` 等 | §3.3 用例；旧测适配字段默认值 |
| 文档 | `README.md`、`docs/方案补记.md` | V1.4 能力与离线安装说明 |

不新建服务进程、不换 waitress、不改双会话协作铁律（见 `AGENTS.md`）。

### 4.2 风险与对策

| 风险 | 对策 |
|------|------|
| 旧任务记录缺 `source_path` | 字段默认空；仅新自动任务走路径分支；上传任务逻辑不变 |
| 转换中源文件被挪走 / 锁定 | 失败可读；不自动死循环重试 |
| 多 script 加载顺序错误 | 固定顺序 + 首页/监听/设置冒烟；打包后 `scripts/smoke.py` |
| Windows 本地包路径权限 | 优先上传到 `tmp` 再解压 |
| 流式上传与大小限制不一致 | 沿用 `MAX_CONTENT_LENGTH` / 设置中的上限；补中断清理测试 |

### 4.3 验收清单

- [ ] 自动转换：大文件按源路径转换，uploads 中无整文件副本（或仅上传任务有副本）
- [ ] CLI / Web 均能解析 `engines/calibre`
- [ ] 断网或下载失败场景下，本地安装包可完成便携安装
- [ ] `app.js` 拆分后页面功能正常；视觉仅小打磨
- [ ] `pytest` 全绿；`python scripts/smoke.py` 通过（打包前）
